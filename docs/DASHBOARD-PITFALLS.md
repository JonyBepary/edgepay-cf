# Dashboard Pitfalls

The 8 mistakes almost everyone hits once on Cloudflare. Each row: what you see → what to do. Short version — copy the fix and move on.

See also: [README](../README.md) · [DEPLOYMENT](DEPLOYMENT.md) · [CRYPTO-NORMS](CRYPTO-NORMS.md) · [SECURITY](SECURITY.md)

| # | Symptom (what you see) | Fix (what to do) |
|---|------------------------|------------------|
| 1 | **Analytics Engine error `10089` / empty charts.** "Dataset not found." | **Do nothing — it auto-creates.** AE datasets are created on the first `writeDataPoint` call, not by hand. Open the app and trigger one event, then recheck. Enable/check AE: `https://dash.cloudflare.com/<account-id>/workers/analytics-engine` — or via API `GET /accounts/:id/analytics_engine/sql`. Docs: [Analytics Engine](https://developers.cloudflare.com/analytics/analytics-engine/) · [writeDataPoint](https://developers.cloudflare.com/workers/runtime-apis/bindings/analytics-engine/). |
| 2 | **D1 works locally but fails after deploy** ("no such table", wrong data). | **You queried local, not remote.** Local and remote are different databases. Always use the **binding name** (`DB`) with `--remote` for live: `npx wrangler d1 migrations apply DB --remote`. Check: `npx wrangler d1 list`. Docs: [D1 + Wrangler](https://developers.cloudflare.com/d1/build-with-d1/) · [Migrations](https://developers.cloudflare.com/d1/reference/migrations/). |
| 3 | **`/install` runs twice / never locks** (wizard stays open). | **Check the KV install lock.** The wizard sets KV key `system:installed` after the first successful run and refuses to run again. If it re-runs, the KV binding is missing or was wiped. Check dashboard → Worker → KV binding `KV` exists; read the flag with `npx wrangler kv key get system:installed --binding KV`. Do not set it by hand — complete the wizard once. |
| 4 | **`/api/admin/*` returns 503.** | **This is intentional — Access is not set up yet.** There is no bypass flag. Create a free Zero Trust team at <https://one.dash.cloudflare.com>, add an Access app covering `https://<your-worker>/api/admin/*`, then set `CF_ACCESS_TEAM_DOMAIN` + `CF_ACCESS_AUD_TAG` and redeploy. Until then admin stays closed (fail-closed). Docs: [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/identity/access/) · [Validating Access JWTs](https://developers.cloudflare.com/cloudflare-one/identity/authorization-cookie/validating-json/). |
| 5 | **Rate limits do nothing / wrong limits apply.** | **You set a zone rule, not the Worker binding.** EdgePay enforces limits with the **Rate Limiting binding** (`RATE_LIMIT_READ`, `RATE_LIMIT_WRITE`) inside the Worker — dashboard zone rules do not affect it. Check `wrangler.jsonc` has the `ratelimits` bindings, quota, and that code reads them per route. Docs: [Rate Limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limiter/). |
| 6 | **No alerts / lost webhooks, queue "just stops".** | **Wire Logpush + AE alerts and check the DLQ.** Queue consumers retry then drop to `webhook-out-dlq`. Set up [Logpush](https://developers.cloudflare.com/logs/about/) for Worker + Queue events, add an AE query alert on error spikes, and drain the DLQ: dashboard → Queues → `webhook-out-dlq` → inspect/redrive. Email/SMS queues (`email-out`, `sms-parse`) each need the same check. Docs: [Queues + DLQ](https://developers.cloudflare.com/queues/configuration/dead-letter-queues/) · [Workers Logs](https://developers.cloudflare.com/workers/observability/logs/). |
| 7 | **Custom domain shows Cloudflare error / wrong Worker.** | **The button skips custom domains.** Add them after deploy: dashboard → Workers → your Worker → Settings → Domains & Routes → Add Custom Domain, then wait for DNS + cert. Apex domains need a proxied A/AAAA or flattened CNAME. Docs: [Custom domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/). |
| 8 | **Workers Builds fails instantly / "blank build command".** | **Set build command + deploy script.** Dashboard → your Worker → Settings → Build → Build command must be `npm run db:migrations:apply && wrangler deploy` (applies D1 by binding name `DB` before upload). Plain `wrangler deploy` skips migrations and the first request fails on missing tables. Docs: [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/) · [Deploy buttons](https://developers.cloudflare.com/workers/platform/deploy-buttons/). |

## Two warnings people miss

- **`token_hash` test warning:** test tokens contain a `token_hash` field for fast lookup. Never log or expose full token values — only the hash prefix. If a hash appears in logs, rotate that token immediately (`POST /api/v1/api-keys` → delete old, mint new).
- **Install-lock KV note:** the lock is the KV key `system:installed`. If you delete the KV namespace, the wizard reopens to anyone. Back up KV or re-complete `/install` immediately after any KV reset.
